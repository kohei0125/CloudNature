### 検出して是正した問題

1. **他記事が削除済みセクション・旧タイトルを参照**（PoC記事のリライトが原因）。
   `niigata-fde-shared-ai-development.ts` の「標準スケジュール（2〜6週間）」「小規模PoCなら40万〜100万円」は
   改稿後の「一律の相場・標準期間はない」と矛盾していたため書き換え。
   `niigata-ai-development-company-guide.ts` の削除済みセクション参照2件・旧タイトル参照3件も修正。
2. **`content/usecases/index.ts` の比較関数が不整合**。同日付で `0` を返さず常に `-1` を返すため、
   同日3本の表示順が配列と逆になっていた。`localeCompare` による降順比較へ修正。
3. **TOPページのクライアントバンドルに全記事本文が載っていた**。
   `components/home/CasesCarouselSection.tsx`（client component）が `@/content/usecases` を import しており、
   記事本文HTMLがブラウザのJSに含まれていた。`USECASES_CARDS`（body を落とした射影）を
   server component から props で渡す形に変更。
4. **未検証の効果数値**。「見積もり作成時間を数日→1分に短縮（工数95%削減）」は測定根拠が未確定だったため、
   新記事では数値を使わずに執筆。その後、代表より実測値（**従来は1件あたり約1時間／お客様に要件を直接入力
   いただく形にしたことで90%以上削減**）の提供を受け、公開済みの7ファイルを実態に合わせて是正した。
   あわせて `CASES_CTA` の「最大95%の工数削減を、御社でも」は成果保証にあたるため表現を変更。
5. **未参照画像18件（1.89MB）を削除**。PoC記事の図解削除等で孤児化していたもの。

#### 指摘2に関する追加調査

`<td><strong>` の一括削除に使った正規表現 `<td><strong>(.*?)</strong></td>`（`/gs`）が、
`<td><strong>定型</strong><br />…</td>` のように `</strong>` の直後が `</td>` でないセルで
マッチを打ち切れず、238行目の `<td><strong>` から333行目の `</strong></td>` までを
1マッチとして置換していた。置換後も `$1` で中身は保持されるため**内容の欠落はなく**、
両端のタグ2個（238行目の `<strong>` と333行目の `</strong>`）だけが失われていた。

Codexが検出したのは前者のみ。後者（`<td><strong>タスク成功率</td>`）は開始・終了タグの
個数が全体では釣り合うため単純なタグ数照合では検出できず、**スタック方式の入れ子検証**で発見した。
3記事すべてに同検証をかけ、現在は入れ子エラー0件。

教訓: HTML文字列に対する複数行マッチの一括置換は、境界が保証されない限り使わない。
実施した場合は必ずスタック方式で入れ子を再検証する。
